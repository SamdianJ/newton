## 2. 实现与语义边界

M2 合并每条 cable 的 raw/Jacobian 提交，继续使用原有分段归约、严格 Jacobian 与接触 factor 零模判断、净 torque 门槛及 FP64 投影均值。trial qualification 的 pins 和 accepted operator 的 pins 分开保留，没有新增经验阈值。

M3 合并 cloth/cable 反力 scatter，保持非连续 particle ids、xyz/theta offset、固定行反力、reference 分支的符号和单次累加。M4 的统一 finite/fixed-theta kernel、一次 4-int 状态回读、三次 D2D 冻结在 PR-01 已实现；本次只补边界和成本证据，没有重复实现。

PR-01 明确留下的 cable element product、absolute operator、gather 和 preconditioner band 提交也在本 PR 合并。各元素内部运算、element-relative product、固定逐元素 gather 顺序、accepted tangent 和全局 PCG 语义保持不变；不提升 FP32 算术精度。

新增私有 `_DeviceRecords` 只绑定原 owner 数组。`(record, local index)` jobs 按实际行/元素数展开，没有按最大对象长度 padding，也没有改成一个线程串行计算整条 cable。数值更新不上传描述符；同形状存储换地址或 strides 变化时，在 capture 外创建新描述符。graph 同时保留描述符和底层数组；旧 PCG plan 拒绝失效绑定。布局、dtype/device 变化要求重建。状态所有权、贡献来源、收敛组、预条件块和独立域没有合并。

材料生产修改集中于 `material_batch.py`、`cable_gauge.py`、`producers.py`、`cable_operator.py`、`cable_preconditioner.py`；另在 `segment_graph.py` 加入下述首捕获防护；新增功能测试和 Towncrier 条目。host 元数据枚举和 signature 构造仍随对象数增长，属于 L1/PR-06；这里关闭的是设备提交/回读成本合同，不能宣称所有 host 工作都为常数。

## 4. 阶段成本与新增存储

1/2/4/8 对象、两精度，CPU eager 16 组和 CUDA eager/graph 32 组的 baseline/current 对照全部通过。下表为单次直接阶段调用的 host `wp.launch` API 次数；reaction 只统计 scatter，完整接触计算的其他调用另存原始记录。

| 操作 | 原实现，N 个对象 | 当前 | N=8 前→后 |
| --- | --- | --- | --- |
| gauge qualify | 2N+4 | 5 | 20→5 |
| material reaction scatter | N | 1 | 8→1 |
| product + magnitude | 4N | 3 | 32→3 |
| absolute coordinates | 3N | 2 | 24→2 |
| cable band + factor | N+1 | 2 | 9→2 |
| control validation | 1 | 1 | 1→1 |

gauge 保持一次 native summary 回读，字节数随 cable 数增长；control 保持一次 16-byte 状态回读和三次 D2D copy。其余直接算子不增加回读；所有阶段的稳态 H2D 均为 0。CPU 的计数代表 `.numpy()` API 调用，不能称为实际 D2H。空 cable control 的零长度 launch/copy API 也被计数，不等于执行了有效设备工作。

CUDA graph 下，gauge 和 reaction 原本已有稳态重放，本 PR 不将其包装成新增 host replay 收益；改动减少捕获内按对象展开的 kernel。`initial_capture_kernel_calls` 仅统计初始化 step 实际触发的捕获。band/product/absolute 表中是直接 API，完整 step/PCG 的 graph 效果由成对测量单独报告。见 `phase-comparison.json` 和四份 `phases-*.json`；最终四份测量绑定干净 baseline 与 `c3dc0714`，捕获防护前记录另存 `material-only-phases/`。

捕获防护新增的是 miss 时的当前 stream 同步，不是 D2H。此次初始化 step 中，CUDA graph cloth/cable 分别触发 20/21 次显式同步，N=1/2/4/8 和两精度保持相同；baseline 为 0。暖后的所有直接阶段对照均为 0 次显式 stream 同步。后续因参数/存储变更而发生的重捕获仍会同步，完整 step 计时包含该等待，独立插桩的 `submits.stream_sync` 单独记录。

当前小 fixture 的新增 descriptor/jobs 设备存储：cloth 为每对象 248 字节，cable 为每对象 2,296 字节，两精度相同；N=8 分别为 1,984 / 18,368 字节。它们不包含原有数值数组、Python 对象、allocator 或 graph 内存。对一般对象，jobs 为实际 reaction 行、gauge work、element、gather 行和 band slot 数乘 8 字节，加每种描述符的固定大小，总量随实际工作量线性增长。

## 6. 开发失败与开放观察

- 保留 struct host 构造调用不被 Warp 支持、kernel 条件数组别名编译失败的初次记录；改用逐字段构造和显式标量读取分支后通过。没有改变求和次序或物理公式。
- reaction 测试曾在切换 reference 模式前写入另一分支的 residual buffer；修正测试准备后通过。输入校验和独立反力断言不变。
- **P9a-OBS-02：已复现并加入捕获边界防护，依赖内部根因尚未归属**。原始 FP32 失败后，FP64 focused test 与热缓存重复都再次失败；保存的 binding=1/replay=0 现场显示 product 正确、magnitude=2G。DOT 的两个 memset、三个 kernel、参数/指针/依赖均正确；jobs 唯一，scratch 独立重建为 G。同一图再次 replay、先写 sentinel 再 replay 以及 eager 均恢复 G。
- 不导入 Newton 的 `warp-only-probe.py` 复现了同样错误；取消 warmup 后，sentinel 17 得到 17+G，证明并非关闭 warmup 就能修复。当前环境为 Warp 1.17、CUDA toolkit 12.9、driver API 12.8（NVIDIA driver 570.211.01）、sm_120；未将现象擅自归因于其中某一层。
- 新的 `test_segment_reset_after_pending_work` 覆盖 warmup 开/关、512 次新捕获及命中重放，在旧实现出现 12 个首执行失败。当前 `_SegmentGraphCache` 仅在 miss 的 warmup 后同步当前 stream，再进行捕获；命中路径仍异步。此机制测试与原独立材料 oracle green，原材料两精度/两绑定重复 200 次 PASS。独立 Warp 的捕获前同步、launch 前同步与 kernel clear 对照各 4,000 次捕获通过。选择现有缓存边界的一次同步，避免逐个替换物理计算中的清零操作。
- 原 FAIL、失败后的观察器脚本错误、正确图参数和后续实验均保留。防护前完整组件 PASS 不覆盖原失败；防护后单列受影响图/线性/材料/接触 stream/发布/小 E2E 回归。此问题可蒸馏为组件机制用例，未修改 quick frozen cases。capture miss 的同步成本已纳入测量合同；依赖层修复或移除此防护必须重新验证，不能把 OBS01 自动归为同一根因。
- 既有 `P9a-OBS-01` checkpoint 观察本轮未复现，仍 OPEN；机器人 alpha/LRU 与整体性能项 `P9a-PERF-01` 仍 OPEN。

M2/M3/M4 的设备批处理成本合同及 PR-01 留下的 cable product/absolute/gather/band 缺口在本 PR 关闭。整体性能资格、P9a-PERF-01 与 OBS01 继续 OPEN；OBS02 的 Newton 防护已通过最终组件/quick 验证，依赖内部归因继续跟踪。下一步为 PR-05 M5。
