## 当前实现

L1 在构造期登记 owner、state、contact batch/material 与 PCG workspace 的字段名，热路径仍读取当前数组并执行绑定检查。合法指针/stride 替换由 graph key 重新捕获；无效 shape/dtype/device 仍拒绝。strided 原生标量输出的有限值检查直接读取本轮数组，避免在计算前复制旧值。

L2 用固定地址的原生精度 dt、alpha、inverse-dt-squared 和 contact falloff buffers 为现有 kernel 提供数值；独立 objective 的标量调用继续可用。参数更新发生于捕获外，dt/alpha 不再构成 graph 参数身份。host dt 先转 Python float 再比较，保留派生量的原舍入顺序；tet 逆平方的验证保持原 assemble 边界。离线 objective replay 不把派生 falloff 当作可独立恢复的物理状态。

开发证据：旧版 `b5868dc4` 的 CUDA 机制测试 3 个预期失败（多 alpha 捕获、热反射、dt 重捕获），另有旧版 PCG 热反射与 strided 输出误读的最小复现。当前固定 working diff 的 CPU 12 个方法 PASS（`binding-final-cpu.json`），包含全部 6 个新机制测试、5 个状态检查及 PCG 绑定。前期 CPU 17 项 PASS 为增量证据；最终干净提交的 CPU/CUDA、quick 与成对性能尚待执行。

L3 尚未改生产策略：正在比较实际 order / pool finish / scalar BSR 的七档循环，并检查一次高峰后的持续小请求。LRU 仍为 6；PR-04 首捕获同步防护保持。机器人性能 harness 在计时外记录动态 span 缓存，避免把合成回退直接当作真实窗口瓶颈。
