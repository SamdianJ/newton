# PR-02：固定绑定 PCG 复用与异常生命周期

2026-11-02。状态：IN_PROGRESS。起点 `e353411f`，对应 H2 / R1；继续使用 `Monolithic-p9a` worktree。

## 目标与实现边界

- workspace 已验证并封存的 assembly 可在固定存储内改变 offsets、columns、nnz 和数值；PCG graph 读取设备中的当前内容。新 generation 不应触发布局大数组回读或重建 plan。
- 保留首次绑定的布局验证，以及 standalone plan 对外部布局变更的检查。保持 generation、scaling、factor、regularization、stream、schedule、容量和 material 绑定检查；不新增无实际所有者的 structure epoch。
- 区分捕获失败与可能已经提交的 replay/enqueue/collect 失败。后者在重新使用缓冲区前排空绑定 stream；排空失败时保持不可复用。失败后禁止收集旧的成功结果。
- 本 PR 不处理 PR-03 packet 融合、PR-06 candidate alpha 缓存或改变求解数值策略。

## 验证顺序

1. 先保存相同物理输入的修改前 D2H、capture/replay 和耗时；添加 H2/R1 失败复现。
2. CPU/CUDA、FP32/FP64 下检查 A/B/A 稀疏内容、零值与 nnz 变化、容量和非法输入；使用独立 dense residual/solution oracle。
3. 注入提交前/提交后、部分 enqueue、capture、collect 和 stream 排空失败；检查非重入、拒绝旧结果和后续合法求解。
4. 运行受影响 linear 组件、小 q+x 和混合 64 步集成；同输入修改后成本对照；两精度 workspace quick。
5. 独立 Fit / Requirements / Standards 审查、pre-commit、更新文档并本地提交。

结果目录：`dev/monolithic/test/results/P9/P9a/PR-02/20261102-01/`。阶段全量 suite/stage 为 NOT_RUN；沿用既有冻结门槛。

## 实现批次与初步验证

只修改 PCG plan 及其测试：workspace 的 finalize 已验证并封存稀疏内容，现有 buffer signature 足以判断绑定变化，无须修改 BSR 构建或增加 epoch。初次构造仍验证布局；standalone 每次 prepare 的布局校验保留。固定容量中的数值、column/offset 和 nnz 变化均由捕获的设备 matvec 实时读取。

异常处置统一由 plan 持有：capture 发射失败使结果失效，未提交时不排空 stream；enqueue/replay/collect 可能已有设备工作时先排空绑定 stream，成功后释放 graph、解除 busy。排空失败保留 graph/buffers 和 busy/failed，拒绝重新准备或收集旧结果。恢复 prepare 时仅对失败过的 plan 清空结果 packet，兼容由外层提交的 CUDA graph，同时禁止“仅 prepare 就收集旧 SUCCESS”。没有增加正常路径同步。

CPU red 2 项、CUDA red 3 项分别复现 H2/R1；修复后 CPU 2 项、CUDA 4 项通过，覆盖两精度稀疏 A/B/A、数值零、满容量、非法索引，以及部分提交、前后 replay、capture、外部 capture、collect 和排空失败。旧“内容变化必重建”断言已迁移到独立残差与 graph 复用，存储替换和 schedule 改变仍重建。

Fit / Requirements / Standards 静态审查完成；两处外部 capture/旧结果边界已修正并纳入测试。正式受影响组件、集成、同输入成本对照及两精度 quick 待受验实现提交后执行。本批不宣称 PR-02 已完成。
