## 2. M1 实现与边界

后验：error/rhs/magnitude/original/regularization 五个向量在同一次固定顺序分段遍历中分别累加，合并已有 PCG 内部范数，形成 native dtype 的 `G×6` packet。每个向量保持原 128 行 chunk 的求和顺序和 host native sqrt；PCG 控制器不变。schema 固定，不按 Python array 身份推断字段。实际 native lambda 为零（含 FP32 下溢）时 original 复用 error、regularization 为零，不读取这两个无效向量；lambda A/B/A 不新增 graph key。

收敛评估：RHS/原始残差范数、归一化残差/参考平方和、scaled tolerance minimum 复用五列分段归约，再与物理 worst、rounding-limited 计数及原 criterion merit square sum 一起读取。线性组与物理组的映射、数量分别保留。仅 assessment packet 的浮点传输字段用 FP64 无损承载两精度，消费前转回 native；计数仍为 int32，不受 FP32 的 2²⁴ 精确整数边界影响。算术和物理门槛没有提升精度。

每次 assessment 从 5 次回读降为 1 次；posterior 从无/有正则化的 4/6 次降为 1 次。两者位于各自真实依赖边界，未提前读取 PCG 或物理计算结果。trial 沿用同一 scratch 的前四列，第五列写零。graph 绑定包含所有实际输入、scratch、输出及 PCG norm buffer，更换存储触发重捕获。

额外修复摘要非有限值边界：NaN residual 可能被物理 atomic max 忽略，旧私有 assessment 曾返回 `converged=True, merit=NaN`。现在同时拒绝非有限 worst 和 merit。正常 evaluate 原已检查 residual，本改动补齐摘要自身的防线；保留 red/green 证据，不改变有效输入的接受策略。

生产修改集中在 `iteration_device.py`、`problem.py`、`iteration.py`；新增 packet 机制测试，迁移 reductions 与 tolerance 测试，并添加 Towncrier 条目。复用同一分段 metadata/partials，继续单 stream、非重入使用，不引入新 owner、公共 API 或 `(5*G,N)` 中间数组。

## 5. 开发失败记录与处置

- `red-cpu` / `red-cuda` 是预期读数断言失败，不是运行错误；CUDA red 约 1114 秒主要用于旧 tet 组合首次编译。`red-nonfinite` 保留旧摘要 NaN 行为。
- 为不修改运行中的 CUDA 基线，草稿曾在隔离 checkout 验证。`green-isolated-cpu` / `packet-compile` 暴露 Warp kernel 不支持该处 `.size`，改成 `.shape[0]` 后通过；失败日志和草稿 patch 保留，不计作最终验收。
- `rebind` 首次 CUDA 断言因 fixture 未开启 production graph 而失败，修正 fixture 后 `rebind-final` 两设备通过，未改生产逻辑。
- 首次 `bbfd16ca` 完整批次 CPU 54 / CUDA 36 各有 1 ERROR，其余无失败。旧 tolerance 测试还读取 `residual_norm_limits=None`；干净起点 `30c49645` 的 `baseline-tolerance` 复现相同错误。仅迁移两处为 `group_norm_limits`，独立公式、断言和门槛不变；隔离 probe 后在 `afe86b7e433a2b32f24b6ba8e89e13b286268164` 重跑完整批次及补充 precision 分支，均通过。原错误批次保留。
