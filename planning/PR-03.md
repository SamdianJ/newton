# PR-03：后验与收敛摘要 packet 融合

2026-11-02。状态：IN_PROGRESS。起点 `30c4964592205c90b045b5dfe0d958c6ac132132`，对应 M1；继续使用 `Monolithic-p9a`。

## 目标与边界

- 后验在同一固定顺序分段遍历中计算 error/rhs/magnitude/original/regularization 五组平方和，合并已有 PCG 内部范数，以一个 packet 读取。schema 固定，不按 Python array 身份判断字段；实际 native lambda 为零时 original 复用 error、regularization 为零。
- 收敛评估合并 RHS/原始残差范数、归一化残差/参考平方和、scaled tolerance minimum，以及物理分组 worst/rounding-limited 和全局 merit square sum。线性分组与物理分组分别保留。
- 保持各向量的分段加法顺序、native sqrt、原 merit 求和、FP32 rounding floor/cap 与公开输出语义。assessment packet 的浮点传输字段用 FP64 无损承载两精度，计数仍是 int32；posterior packet 使用 solver native dtype，算术不提升精度。
- 复用预分配分段 scratch，仅使用 O(N) 行项和 O(chunks×K + G×K) 摘要；不创建 `(5*G,N)` 数组，不改 PCG 控制器、物理门槛或默认预算。
- 同时检查摘要 merit 的有限性：修复前已复现 NaN residual 被物理 atomic max 忽略、却返回 converged 的私有评估边界。正常求值已有残差有限性检查，此处补齐摘要自身的拒绝条件。

## 验证顺序

1. 原版本 CPU/CUDA 上先验证每次 assessment 有 5 次读取、posterior 在无/有正则化时有 4/6 次读取，新增单 packet 断言必须失败；另复现 NaN 摘要边界。
2. 用独立 NumPy 公式检查两精度、零/空/非连续组、大动态范围、NaN/Inf、lambda A/B/A/下溢、物理与线性组数量不同、超过 FP32 精确整数范围的计数；覆盖 graph replay 和失效绑定。
3. 受影响 reductions/convergence/direction/precision oracle/linear tolerances、小 q+x 与混合 64 步 checkpoint/rollback 集成。
4. 复用 PR-01 小场景脚本，在 PR-03 起点与最终实现间做三组成对测量；逐项比较输入/配置/工作量、回读与提交数量、median/P95。机器人性能与整个 `P9a-PERF-01` 不凭局部收益关闭。
5. 最终提交执行 workspace quick FP64/FP32、独立 Fit/Requirements/Standards 审查、pre-commit、Towncrier preview，然后更新状态与证据索引。
