## M5 实现与消费者

最终 residual、cloth/cable reactions 在原边界调用私有 `_diagnostic_snapshot`，以 `.numpy().copy()` 取得独立的原生精度 NumPy 数组，再设置只读。CPU `.numpy()` 可能别名 solver 存储，因此保留显式 copy。没有逐 Newton 轮列表、公共开关、惰性包装或新序列化协议。最终完整向量回读仍存在，反力快照仍按材料对象生成；本 PR 处理 Python 对象分配，不宣称减少 D2H。

现有 `monolithic_recording.serial/save` 已递归处理 ndarray、元组和非有限值，JSON 仍为列表及 null。数值消费者的 reduction/gate 保留显式 float 转换，其余是切片/abs/max。两处持久化 `str(Stats)` 的 runner 保留 `failure-stats.txt`，同时写完整 `failure-stats.json`，避免 NumPy repr 截断大向量。消费者盘点见结果目录 `consumer-audit.md`。

## 生命周期合同

| 出口 | residual / reactions |
| --- | --- |
| Converged / Stopped 发布 | 最终验证候选的 residual，以及发布阶段的材料 raw reactions |
| 迭代硬失败 | 最后一次已报告的 residual；首次报告前失败则没有 residual，未到发布阶段则没有 reactions |
| 发布后段失败或普通异常 | 可能保留被回滚候选的 residual/reactions；用 `rolled_back` 与 `step_generation` 解读，不当作输出状态的有效反力 |
| 进入迭代前的输入拒绝 | 保持上一份 Stats |

无论后续正常步、失败步或 solver scratch 被覆盖，已持有 Stats 的向量都保持不变。新增测试检查真实写入拒绝、原生 dtype、CPU 内存不共享、前后两步快照互不共享及 JSON 数值逐项一致。

## 测量合同

同 RTX 5070 Ti Laptop GPU、Warp 1.17.0、NumPy 2.5.0、NVIDIA driver 570.211.01，两个干净 checkout 串行 AB/BA/AB。12 个全步组合：q+x、1/8 组 cloth+cable × 两精度 × 无导出/完整 JSON。每进程每组合 4 个 warmup + 7 个 timed samples，共 21 个样本/版本；恢复输入和前置 barrier 不计时，末尾完成 barrier 计时，任何稳态重捕获仍计时。每步记录 nonlinear segment graph 增量，不将其解释为所有图缓存。

主机 tracing 和传输/提交来自各一条独立恢复样本，与所有 timed samples 严格核对物理工作量。`traced_live/peak` 是 tracing 捕获的新分配，包含保留的 JSON 字符串，不是进程 RSS 或完整 native/CUDA 内存。`retained_vector_bytes` 含容器和对象开销；CPU 有效载荷读取不称 D2H。完整 JSON 的计时字段可能使字节数自然浮动，向量数据独立用哈希对照。

另测 CPU/CUDA、FP32/FP64、1024/65536 行、是否完整 JSON 的隔离快照；它解释列表分配成本，不作为完整场景吞吐资格。P95 仅是 21 个小样本的描述性统计。

## 隔离快照与真实导出成本

65,536 行原生向量的保留存储由 2,097,208 B 降到 FP32 262,256 B / FP64 524,400 B，约减少 87.5% / 75.0%。这不包含 solver scratch，也不代表整场景内存；1024 行及全部 16 个组合见 `paired-summary.json`。

| 设备 | 精度 | 无导出 median/P95（ms） | 完整 JSON median/P95（ms） | 完整 JSON traced peak（B） |
| --- | --- | --- | --- | --- |
| cpu | FP32 | 0.606/0.644 → 0.007/0.011 | 40.115/41.240 → 39.119/39.336 | 4,384,332 → 4,122,404 |
| cpu | FP64 | 0.616/0.695 → 0.020/0.026 | 38.407/39.270 → 38.211/38.742 | 4,070,160 → 4,070,376 |

CUDA 不导出快照 median 约降低 89.6%/80.3%，三组均下降；但加上完整 JSON 后仍约 39 ms（FP32 +0.3% / FP64 -0.9%，小样本描述性差异）。导出仍需要 Python 列表与逐项处理，其成本没有被隐去。该大向量的 JSON 字节严格一致：FP32 1,383,796 B / FP64 1,383,813 B；CUDA 读回有效载荷仍是 262,144 / 524,288 B，CPU 对应的是本机读取。
